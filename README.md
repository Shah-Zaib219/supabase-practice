# supabase-practice

A Flutter practice app that connects to [Supabase](https://supabase.com) for:

1. **Configuration**: setting up the Supabase client in Flutter
2. **Authentication**: sign up, log in, and log out with email and password
3. **CRUD on a list**: create, read, update, and delete rows in a `lists` table

It uses the [Stacked](https://stacked.filledstacks.com) architecture (views + view models) and a custom Material 3 theme.

## Screens

| Screen | What it does |
|---|---|
| **Startup** | Gradient splash screen, waits 3 seconds, then opens Login |
| **Login** | Email and password sign-in through Supabase Auth |
| **Signup** | Creates a Supabase account (password must be at least 6 characters and match the confirmation) |
| **Home** | Form with title and description, plus the list of saved items with edit and delete |

## Tech stack

- Flutter (Dart SDK `>=3.0.3`)
- [`supabase_flutter`](https://pub.dev/packages/supabase_flutter) `^2.18.0`
- [`stacked`](https://pub.dev/packages/stacked) and [`stacked_services`](https://pub.dev/packages/stacked_services) for MVVM, navigation, and dialogs

## 1. Configuration

### Supabase project

1. Create a project at [supabase.com](https://supabase.com).
2. Go to **Project Settings → API** and copy the **Project URL** and the **publishable key**.
3. Go to **Authentication → Sign In / Providers → Email** and turn off **Confirm email**. That way `signUp` signs the user in straight away.

### Create the `lists` table

Run this in the **SQL Editor**:

```sql
create table public.lists (
  id          bigint generated by default as identity primary key,
  title       text not null,
  description text,
  created_at  timestamptz default now()
);
```

> For this practice, **Row Level Security (RLS) is off** on `lists`. See [Security notes](#security-notes).

### Flutter setup

Add the packages:

```bash
flutter pub add supabase_flutter flutter_dotenv
```

#### Keys in a `.env` file

The Supabase keys are kept in a `.env` file instead of the code. `.env` is listed in `.gitignore`, so it is **not** in this repo. Copy the template and fill in your own values:

```bash
cp .env.example .env
```

```env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

Register `.env` as an asset in `pubspec.yaml` so Flutter can load it:

```yaml
flutter:
  assets:
    - .env
```

#### Initialize Supabase

In `main.dart`, load `.env` and then initialize Supabase, both **after** `WidgetsFlutterBinding.ensureInitialized()`:

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await dotenv.load(fileName: '.env');
  await Supabase.initialize(
    url: dotenv.env['SUPABASE_URL']!,
    publishableKey: dotenv.env['SUPABASE_PUBLISHABLE_KEY']!,
  );
  await setupLocator();
  setupDialogUi();
  setupBottomSheetUi();
  runApp(const MainApp());
}
```

> `anonKey` is deprecated in `supabase_flutter` v2. Use `publishableKey`.

Anywhere in the app you can then get the client with:

```dart
final supabase = Supabase.instance.client;
```

## 2. Authentication

In `supabase_flutter` v2, auth calls **throw an `AuthException`** when they fail. They don't return an error object, so each call goes in a `try/catch`.

### Sign up: `signup_viewmodel.dart`

```dart
try {
  await runBusyFuture(
    supabase.auth.signUp(email: email, password: password),
    throwException: true,
  );
  _navigationService.clearStackAndShow(Routes.homeView);
} on AuthException catch (e) {
  errorMessage = e.message; // e.g. "User already registered"
  rebuildUi();
}
```

### Log in: `login_viewmodel.dart`

```dart
try {
  await runBusyFuture(
    supabase.auth.signInWithPassword(email: email, password: password),
    throwException: true,
  );
  _navigationService.replaceWithHomeView();
} on AuthException catch (e) {
  errorMessage = e.message; // e.g. "Invalid login credentials"
  rebuildUi();
}
```

### Log out: `home_viewmodel.dart`

```dart
await supabase.auth.signOut();
_navigationService.clearStackAndShow(Routes.loginView);
```

`runBusyFuture` (from Stacked) sets `isBusy` while the request runs, and the submit button uses it to show a spinner.

## 3. CRUD on the `lists` table

All of the CRUD code is in `lib/ui/views/home/home_viewmodel.dart`. Database errors come back as a `PostgrestException`.

### Read

```dart
final data = await supabase
    .from('lists')
    .select()
    .order('id', ascending: false);
items = List<Map<String, dynamic>>.from(data);
```

The list loads when Home opens (`onViewModelReady`) and reloads when you pull it down.

### Create

```dart
await supabase.from('lists').insert({
  'title': title,
  'description': description,
});
```

### Update

Tapping ✏️ on an item fills the form, and the button then says **Update**:

```dart
await supabase
    .from('lists')
    .update({'title': title, 'description': description})
    .eq('id', editingId);
```

### Delete

Tapping 🗑️ asks for confirmation first, then runs:

```dart
await supabase.from('lists').delete().eq('id', item['id']);
```

## Security notes

- The publishable key is meant to ship inside client apps. It's only safe when **RLS** controls what it can do.
- RLS is **off** on `lists` in this practice project, so anyone who has the key can read, change, or delete every row. Every user also shares the same list.
- To give each user their own items:

  ```sql
  alter table public.lists add column user_id uuid default auth.uid();
  alter table public.lists enable row level security;

  create policy "Users manage their own items"
    on public.lists for all
    to authenticated
    using (auth.uid() = user_id)
    with check (auth.uid() = user_id);
  ```

  The app code doesn't need to change: the default fills in `user_id`, and the policy filters the rows.
